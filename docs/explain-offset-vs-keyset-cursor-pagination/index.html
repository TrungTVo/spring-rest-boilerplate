Cursor pagination is optimized because the API sends the last seen ID as after_id. MySQL can jump directly to that indexed boundary and scan only the next page.

Offset SQL and API

Offset is easy to call because the client can ask for any page number. The cost grows because MySQL still walks the skipped IDs.

Cursor SQL and API

Cursor pagination sends the last ID from the previous page. With PRIMARY KEY(id), MySQL can seek to that ID and continue forward.

The mental model

Offset

Page 5 with page size 10 means: skip 40 rows, then return 10. Those skipped rows are not free; the engine must walk past IDs 1 through 40 first.

Cursor

Page 5 with page size 10 means: you already ended page 4 at ID 40, so ask for IDs greater than 40 and return the next 10.

Index

For this simplified ascending example, the useful index is just the primary key: PRIMARY KEY(id).
